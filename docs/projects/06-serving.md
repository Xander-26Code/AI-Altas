# 项目 06 · 推理服务的质量、延迟和吞吐

这是项目任务书，未附 GPU benchmark。先修：[推理服务](../topics/19-inference-serving.md)、基础网络和统计。选择符合设备条件的引擎；记录软件与模型版本，不给未测试硬件的性能保证。

## 实施顺序

1. 定义请求输入/输出长度分布、到达方式、超时和服务目标。
2. 固定模型、精度、数据和质量检查；预热后测单请求基线。
3. 分别增加并发或到达率，记录 TTFT、TPOT、请求总时延的 p50/p95、吞吐、错误与超时。
4. 只改变一个优化：批处理、量化、前缀缓存或推测解码。保持其他条件一致。
5. 检查输出质量、真实完成率与尾延迟；解释饱和后排队如何变化。

## 交付

提交负载脚本、硬件/软件配置、原始日志、统计定义、结果图和失败请求数。区分请求/秒、输入 token/秒、输出 token/秒；缓存命中率和输出长度变化必须披露。

不要把仅成功请求的低延迟当作全体表现，也不要把估算器结果写成实测。没有 GPU 时可做调度模拟，但报告必须标为模拟。
