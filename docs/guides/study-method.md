# 学习、实验与论文阅读方法

## 把输入变成可检查的输出

读一节资料后，合上页面，用自己的话解释一个机制，再写一个最小例子验证。能认出公式不等于能推导；能运行 notebook 不等于能从空文件实现。遇到不会的内容，记录具体卡点，例如“广播后的维度不确定”，而不是笼统写“数学不好”。

每个阶段保留一个主教材。补充资料用于解答具体问题，不要求并行完成所有课程。把阅读、练习、调试和复盘都计入学习时间；长时间停在一个难点并不罕见，路线是预算而非截止日期。

## 每周复盘

| 问题 | 有效记录示例 |
|---|---|
| 我学会解释什么？ | 能说明为什么先切数据再拟合标准化 |
| 有什么运行证据？ | 保存配置与指标，另一个种子也能复现 |
| 哪个假设被否定？ | 增大网络没有改善验证误差 |
| 下周最小任务是什么？ | 固定其他条件，对比两种正则强度 |

## 论文分三轮读

第一轮确认问题、任务假设、输入输出、关键结论和局限，判断与自己的问题是否相关。第二轮跟公式检查维度、目标函数和方法成立条件，建立与基线的差异表。第三轮追踪实验数据、实现、超参数、预算和消融，挑一个可复现的结论。

不懂一个背景概念时，回到主教材或原始参考文献。不要在尚未确定问题是否有价值前，耗尽时间逐行翻译所有段落。

## 实验记录最少要有什么

```text
问题与假设：
固定条件 / 唯一改变的变量：
数据来源、许可、切分和哈希：
依赖、代码版本、模型 revision、随机种子：
训练预算、设备、评估脚本：
基线、结果和不确定性：
失败案例与后续动作：
```

让 AI 辅助解释、生成练习或排查错误时，仍需回到原资料和运行证据核对。要求工具给出可检验的假设，比接受一段流畅的结论更有用。模型生成的引用和实验数字必须验证。
