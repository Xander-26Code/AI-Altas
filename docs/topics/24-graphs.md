# 24 · 图学习与知识表示

> 目标：把关系结构建模为图，区分知识图谱、图算法与图神经网络。先修：[线性代数](01-math.md)、[机器学习](04-machine-learning.md)、[深度学习](05-deep-learning.md)。建议主动学习 35–60 小时。

## 为什么不把所有数据都当表格

一篇论文的主题不仅取决于摘要，还与引用它的论文有关；分子的性质不仅取决于有哪些原子，还取决于原子如何连接。图把对象作为节点，把关系作为边。关系可以有方向、类型、时间和权重；这些选择会改变“邻居”的含义。

知识图谱着重表达实体和关系，图神经网络着重在图上学习表示。一个知识图谱不必使用神经网络，一个 GNN 的输入也不必是知识图谱。图数据库是一种存储与查询工具，同样不等于以上两个概念。

## 学习顺序

1. 邻接表、邻接矩阵、路径、连通分量、中心性和 PageRank。
2. RDF 三元组、实体标识、关系类型、模式约束与实体链接。
3. 节点、边和整图任务；区分 transductive 与 inductive 设置。
4. 消息传递、GCN、GraphSAGE、GAT；先理解置换不变性与邻域聚合。
5. 采样、异构图、动态图、图 transformer 与几何等变模型。
6. 应用到推荐、分子建模或知识检索，先建立不使用关系的基线。

## 核心概念：图上的一次消息传递

一种通用形式是：`m_v = AGG({h_u : u ∈ N(v)})`，再把节点自身状态 `h_v` 和邻居消息 `m_v` 输入可学习更新函数。聚合通常取求和、均值或注意力加权，不能依赖邻居在文件里的排列顺序。

例如，一个节点有两个邻居，特征分别为 `(1,0)` 与 `(0,1)`。均值聚合得到 `(0.5,0.5)`，即使交换邻居顺序结果也一样。堆叠两层后，节点可间接接收两跳邻居信息，但更多层不必然更好：表示可能越来越相似，远处信息还可能被压进有限向量容量。

一层 GNN 的“邻居信息”也可能造成数据泄漏。如果要预测未来才出现的连接，训练图不能提前包含它。是否允许看到测试节点的特征，取决于 transductive 或 inductive 任务定义；先写清协议，再计算指标。[Stanford CS224W](https://cs224w.stanford.edu/)

## 核心知识地图

| 范畴 | 重点 | 检验问题 |
|---|---|---|
| 图算法 | BFS、最短路、中心性、社区 | 简单结构信号能否解决任务？ |
| 知识表示 | 三元组、ontology、实体消歧 | 同名是否同实体？来源可否追踪？ |
| 图表示学习 | 消息传递、采样、读出函数 | 对节点重编号是否保持等价？ |
| 训练协议 | 节点/边/图切分、负边采样 | 未来边或测试标签有没有流入训练？ |
| 模型局限 | 过平滑、过压缩、同配性假设 | 异配图上性能为什么下降？ |
| 检索结合 | 子图检索、图路径、证据整合 | 图结构是否真的改善答案可追溯性？ |

## 实践：引用网络分类

选择公开小型引用图，记录数据许可和官方切分。做三个基线：只预测最多类别；仅用节点特征的 MLP；同时使用图结构的 GCN。保持训练轮数预算和调参次数尽量一致，比较宏平均 F1、各类别表现与峰值内存。

验收需提供：图的节点/边数量、切分说明、三种模型的多种子结果，以及两项消融——随机打乱边、移除节点特征。若 GCN 没有胜出，应解释结构噪声、同配性或超参数影响，而不是删除失败结果。增加节点重编号检查，确认预测没有意外依赖编号。

知识图谱方向可以给 30 个 AI 概念手工建立“先修于/用于/实现于”关系，加上每条边的证据。比较普通词法检索与一跳扩展检索；这也是改进本 Wiki 知识导航的可贡献项目。

## 易踩的坑

- 一张图画得复杂不代表关系质量高，错误实体合并会污染所有下游路径。
- GraphRAG 不是对所有语料都有效，应先确认问题需要跨实体关系。
- 某个图 benchmark 的好成绩不能证明对新图、新时间段或新关系泛化。
