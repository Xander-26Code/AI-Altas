# 27 · 经典 AI、搜索、规划与优化

> 目标：认识不依赖大模型训练的 AI 方法，知道何时使用搜索、约束求解和规则推理。先修：[编程与数据结构](02-programming.md)、基础离散数学。建议主动学习 35–60 小时，CPU 足够。

## 为什么它仍值得学

排课、路径规划、调度、游戏对弈和配置验证，通常有明确状态、动作、约束与目标。模型可以帮你提取信息或生成候选，但硬约束是否满足、计划成本是否最优，还需要可以检验的算法。

经典 AI 不等于过时的方法集合。启发式搜索、逻辑表示、规划、概率推理和学习系统可以组合使用。一个可靠的应用常把“产生候选”和“验证候选”分开，这也适用于现代 Agent。

## 学习顺序

1. 用状态空间表述问题，写清初始状态、合法动作、转移与目标。
2. BFS、Dijkstra、A*；理解搜索树与状态图的区别。
3. Minimax、alpha-beta、Monte Carlo Tree Search，连接博弈与序贯决策。
4. 命题逻辑、一阶逻辑、规则系统、SAT/SMT 与约束满足。
5. STRIPS/PDDL 思想、任务规划和组合优化；按问题选求解器。
6. 进化算法、遗传编程、多目标优化，再研究学习与符号方法的结合。

## 核心概念：A* 的启发式不是随便猜

A* 用 `f(n)=g(n)+h(n)` 选择待扩展节点，`g` 是已付出的路径代价，`h` 是到目标的估计。若启发式不高估真实剩余成本，则称为可采纳；在图搜索中，最优性还和一致性、重复节点处理及重新打开策略有关。

在只能上下左右移动、每步成本为 1 的网格上，曼哈顿距离可作为下界。障碍只会让实际路径更长，不会让直达所需步数减少。如果允许低成本对角移动，原来的曼哈顿距离就可能高估，原先的保证不能照搬。

启发式好坏影响展开多少节点；正确性条件影响能否得到最优解。把这两点分开，才能既做性能优化又保留明确的保证。[Berkeley CS188](https://inst.eecs.berkeley.edu/~cs188/archive/fa24/)

## 核心知识地图

| 方法 | 适合的问题 | 要关注的边界 |
|---|---|---|
| 图搜索 | 路径、状态可达性 | 状态爆炸、重复状态、启发式条件 |
| 博弈搜索 | 双方或多方决策 | 信息可见性、随机性、预算限制 |
| CSP / SAT / SMT | 排课、配置、逻辑验证 | 建模是否正确、求解超时与未知状态 |
| 规划 | 有前提与效果的动作序列 | 环境变化、执行失败、重新规划 |
| 运筹优化 | 路由、资源分配、调度 | 最优性间隙、软硬约束、可行性 |
| 进化计算 | 不易求导、离散或多目标搜索 | 样本效率、随机性、无最优保证 |
| 神经符号 | 学习感知 + 结构化推理 | 感知不确定性如何传入验证环节 |

## 实践：给求解器一个可以检查的任务

实现 BFS、Dijkstra 和 A*，在同一组固定网格上比较路径成本、扩展节点数与运行时间。对小网格用 BFS 的结果作为单位成本最短路基线。加入不可达目标、起点等于终点、包含障碍和不同权重的情况。

验收要求：可视化路径、记录状态去重规则、列出启发式条件；在单位成本测试集合中，A* 必须与 BFS 的最优成本一致。进阶时刻意使用高估的启发式，找出一个返回次优解的反例，解释性能与保证的差别。

约束分支可做“5 人、7 天”的排班：每人工作上限、每天最少人数、禁止连续夜班。把解交给独立检查函数，逐条验证硬约束。求解器超时后拿到的可行解不应写成已证明最优。

## 易踩的坑

- 一段自然语言计划听起来合理，不意味着所有动作前提都满足。
- 目标函数容易算不代表它正确表达了真实需求。
- 对离散问题强行使用梯度下降，可能不如直接使用组合求解器。
- 只报告找到一个解，却不检查可行性和最优性状态，会误导读者。
