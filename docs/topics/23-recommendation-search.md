# 23 · 推荐系统与信息检索

> 目标：理解从海量候选到少量结果的流程，能够设计不泄漏未来信息的离线评估。先修：[机器学习](04-machine-learning.md)、[数据工程](03-data.md)。具备先修后，系统学习主教材、做练习并完成一个项目，建议预留 **100–180 小时**。补先修另计；小数据可用 CPU。

## 从一个产品问题出发

搜索是用户明确表达需求后寻找相关内容，推荐则常需从历史行为和上下文推断需求。它们会共享向量表示、索引和排序技术，但目标不完全相同。用户没点击，不意味着不喜欢；也可能根本没有看到。这使曝光偏差、位置偏差、冷启动与反馈回路成为算法的一部分。

## 学习顺序

1. 倒排索引、分词、TF-IDF、BM25，先做可以解释的文字检索。
2. 集合相似度、协同过滤、矩阵分解，建立热门榜和相似物品基线。
3. 双塔召回、负采样、近似最近邻（ANN），理解“快”来自哪些近似。
4. 特征交叉、学习排序与多目标排序，区分召回和精排职责。
5. 时间切分、曝光日志、在线实验与反事实评估，再考虑长期用户价值。
6. 大规模 embedding 表分片、在线特征一致性、索引更新，连接 AI Infra。

## 核心概念：先召回，再排序

假设有一百万篇文档，昂贵的交叉编码器逐一打分很难满足交互延迟。先用倒排或双塔向量索引找出 200 条，再用复杂模型排序，最后结合去重、权限和多样性输出 10 条。如果正确文档从未进入这 200 条，后面的模型再好也无法把它补回来。

`Recall@K = 前 K 条中的相关结果数 / 全部已标注相关结果数`。当每个查询仅有一个相关结果时，它退化为是否命中的指标；多相关结果时，不要把 Hit Rate 误写成 Recall。

排序常用 `DCG@K = Σ (2^rel_i - 1) / log2(i + 1)`，再除以同一查询理想排序的 DCG 得到 NDCG。必须定义相关性标注、候选集合和无相关结果查询的处理方式，两个实验的分数才可比较。[Introduction to Information Retrieval](https://nlp.stanford.edu/IR-book/)

## 核心知识地图

| 模块 | 知识点 | 需要回答的问题 |
|---|---|---|
| 检索基础 | 倒排、BM25、字段权重、查询扩展 | 专有名词为何可能更适合词法召回？ |
| 表示学习 | embedding、双塔、对比学习 | 负样本分布怎样影响相似度？ |
| ANN | Flat、IVF、HNSW、PQ | 速度、内存、召回率如何权衡？ |
| 推荐建模 | 协同过滤、序列建模、特征交互 | 新用户和长尾物品怎么办？ |
| 排序与目标 | pointwise / pairwise / listwise | 点击率和满意度是否一致？ |
| 评估与实验 | 时间切分、A/B、置信区间 | 结果是否只是热门内容占优？ |
| 工程闭环 | 特征服务、索引更新、在线监控 | 离线特征和上线特征是否一致？ |

## 实践：推荐结果有没有超越热门榜

使用一个固定版本的 MovieLens 数据，按全局时间边界构造训练、验证和测试，确保每次预测只使用当时可见的信息。先写热门榜，再实现物品协同过滤；有余力再做双塔。明确新用户、新物品的处理策略，并始终在同一候选集比较。

验收材料应包含：时间边界、用户覆盖率、Recall@10、NDCG@10、热门/长尾子组表现、推理延迟和 5 个案例解释。如果负采样测试而不是全量候选测试，报告里必须写明采样策略，不能直接和全量指标比较。

也可以先运行本仓库 [检索实验](../projects/02-retrieval.md)：它不需要下载数据或调用模型，用小型中文知识库把召回、拒答和评估接起来。

## 易踩的坑

- 先按完整数据统计热度，再划分训练测试，会引入未来信息。
- 向量相似度高不保证内容相关，ANN 搜索正确也不保证 embedding 学得好。
- 推荐指标上升可能牺牲多样性、覆盖率或长期目标，需明确业务权衡。
- RAG 引用错误时，先检查候选文档和切块，不能只调生成模型。
