# 贡献指南

优先修正影响学习的内容：错误概念、失效链接、不清楚的先修、无法复现的步骤与不合理的时间预期。新增资源应回答“它解决哪个学习问题”，而不是只增加链接数量。

## 资源标准

优先原作者、大学、机构或项目维护者提供的页面。记录 title、url、kind、language、level、access、compute、why、topics、checked_on、verification 和 evidence。日期应对应实际检查日期；别把仅搜索到的页面记为已查看正文。

`content-reviewed` 表示核实过页面内容或目录，不表示完成课程或运行所有代码。`search-verified` 用于只能通过可靠官方索引确认的情况。访问受限时应附可用的官方入口，并说明限制。

## 专题与项目标准

专题按目标与先修、资源列表、基于资源的学习顺序、实践验收与误区组织，不设独立概念讲解部分。学习计划每一步必须对应已列出的资源，说明章节或主题范围、练习与完成证据；明确主线、替代课和选修。时长使用宽范围规划，说明包括哪些活动和先修假设，不给没有依据的速成承诺。项目区分已有代码、已运行实验和待实现任务。

贡献实验需要数据权限、固定切分、基线、环境、指标和失败分析。不要上传课程受限答案、付费教材、个人数据、模型密钥或未经授权的资源副本。

## 提交前

执行 [维护文档](guides/maintenance.md) 的检查。修改源资源数据后更新生成目录；不要直接修改自动生成的 `docs/map.md`、`docs/resources.md` 或 `docs/assets/resources.json`。

PR 描述应说明具体问题、修改、验证和仍未确认的地方。失效链接需要提供原 URL、出现问题的页面、检查日期与推荐替代入口。许可现状尚待仓库所有者确定；新增第三方内容需保留原始授权边界。
