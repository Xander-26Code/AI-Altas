# 开始之前：选方向，跑一个实验

你只需要决定这一阶段想做成什么。第一天不必收藏几十个链接，也不必购买 GPU。

## 判断自己的起点

| 自测问题 | 如果暂时做不到 | 如果已经能做 |
|---|---|---|
| 能否写函数、读 CSV、处理列表和报错？ | 从 [编程](topics/02-programming.md) 和 [零基础路线](roadmaps/beginner.md) 开始 | 做下一项 |
| 能否解释训练集、验证集与测试集的分工？ | 读 [机器学习](topics/04-machine-learning.md) | 可以开始一个建模项目 |
| 能否解释梯度下降和矩阵维度？ | 边做 [回归实验](projects/01-regression.md) 边补 [数学](topics/01-math.md) | 可进入深度学习与模型路线 |
| 能否实现 HTTP 服务并调试超时？ | 在应用路线补编程和网络基础 | 可从 [应用开发](roadmaps/application.md) 起步 |
| 能否解释内存、带宽、并行与瓶颈？ | 先读 [硬件系统](topics/16-hardware-systems.md) | 进入 [AI Infra](roadmaps/infra.md) |

这些是路径提示，不是正式考试。能讲概念但没写过代码，仍建议完成实验；写得出代码但说不清原理，可以沿相应章节补齐。

## 第一次学习可以做什么

1. 浏览 [知识地图](map.md)，选一条主路线。
2. 在环境准备好后运行 [线性回归](projects/01-regression.md) 或 [检索](projects/02-retrieval.md) 实验。
3. 改变一个条件：学习率、查询表达或 top-k，记录结果。
4. 写下“我解释得清的一件事、还解释不清的一件事、明天的一个任务”。

没写过 Python 的读者先完成环境和语法入门，不要求第一天理解完整实现。会开发的读者可直接运行检索，检查失败查询。

## 怎样看每章的资料

每章先列资源，再提供“按资源安排学习顺序”表。先看表前的主线建议，选择一套课程；按表中的阅读范围和产出推进。标注“或”“二选一”的材料是替代选项，选修可留待项目需要时再读。标注“研究”的资料通常适合在完成基础实验后阅读。

| 标注 | 意义 |
|---|---|
| 入门 / 进阶 / 研究 | 本 Wiki 的阅读建议，不是官方课程评级 |
| 免费 / 部分免费 / 付费 | 资料获取边界；云算力、证书、实体书或硬件另算 |
| CPU / 可选 GPU / GPU / 无 | 建议学习活动的算力；大型完整复现可能远超入门配置 |
| content-reviewed | 核实过页面正文或课程目录，不表示精读完全部内容 |
| search-verified | 依据官方搜索索引核实，页面抓取受限；未标为已读取全文 |

## 建一个自己的学习记录

复制下面的表到个人笔记，每周只追踪当前阶段。不要把“看过视频”当作唯一进度。

| 本周任务 | 证据 | 结果 | 下一步 |
|---|---|---|---|
| 例如：解释过拟合 | 一张训练/验证损失图 | 小数据时验证误差回升 | 加入正则并固定其他条件 |
| 例如：检索对照 | 20 个查询的指标与失败样例 | 专有名词查询失败 | 比较字符粒度与词粒度 |

每周投入少于 5 小时时，延长路线周数，保留实验与复盘；不要通过跳过验证来制造完成感。每阶段的小时数是本 Wiki 的粗略规划预算，实际进度因背景和项目范围而异。
